# Objection Handling

## "We do not have budget."

Response:
That makes sense. The first question is whether the current problem is costing more than the project. If the team is losing hours, missing revenue, or creating compliance risk, we can frame the smallest version that pays back quickly.

Proof to prepare:
- Manual hours lost per week
- Revenue leakage or missed opportunities
- Cost of errors, delays, or rework

## "We are not ready."

Response:
Readiness usually comes down to scope. We can start with one workflow, one team, or one reporting need instead of a full rollout.

Proof to prepare:
- Pilot workflow
- Named owner
- Two-week or four-week success criteria

## "We already use another tool."

Response:
The goal is not to replace a tool for the sake of it. The question is where the current setup is still forcing manual work or weak visibility.

Proof to prepare:
- Integration notes
- Migration risk
- Gaps in current workflow

## "How do we know this will work?"

Response:
We can define proof before rollout: one workflow, expected output, owner, and measurable result.

Proof to prepare:
- Relevant sample
- Demo path
- Pilot acceptance checklist
